## Editing behavior that keeps BPMN consistent

| Edit                            | Semantic update                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Create a flow node              | added to the owning process’s `flowElements`; BPMNShape added to the plane                                                                                                                                                                                                                                                                                   |
| Connect                         | `bpmn:SequenceFlow` with `sourceRef`/`targetRef`, plus `outgoing`/`incoming` on both ends                                                                                                                                                                                                                                                                    |
| Delete a node                   | connected flows deleted first; node removed from `flowElements` and every lane’s `flowNodeRef`                                                                                                                                                                                                                                                               |
| Delete a flow                   | removed from `incoming`/`outgoing`; a gateway’s `default` pointing to it is cleared                                                                                                                                                                                                                                                                          |
| Reconnect                       | references moved to the new endpoint                                                                                                                                                                                                                                                                                                                         |
| Change type                     | new object of the new type **with the same id**; name, documentation, extensions, vendor attributes and compatible properties carried over; all references re-pointed. Refused when content would be lost or a flow would become invalid                                                                                                                     |
| First pool on a process diagram | `bpmn:Collaboration` created, the plane points to it, the participant references the existing process                                                                                                                                                                                                                                                        |
| Further pools                   | new `bpmn:Process` per pool                                                                                                                                                                                                                                                                                                                                  |
| Add lane                        | `bpmn:LaneSet` (or the parent lane’s `childLaneSet`) created on first use; pool and enclosing lanes grow; content after it shifts (down, or right in a vertical pool)                                                                                                                                                                                        |
| Move between lanes              | `flowNodeRef` recomputed from node centers                                                                                                                                                                                                                                                                                                                   |
| Move to another pool            | node (and sequence flows inside the moved set) move to the other process; only allowed when no sequence flow would cross pools                                                                                                                                                                                                                               |
| Connect across pools            | `bpmn:MessageFlow` in `collaboration.messageFlows` (gateways, start-event sources and end-event targets are rejected)                                                                                                                                                                                                                                        |
| Data association                | to an activity: a `bpmn:DataInput` in its `ioSpecification` (created with an input and output set when missing) and the first input set; from an activity: a `bpmn:DataOutput` likewise; with events: the event’s `dataInputs` / `dataOutputs` (BPMN 2.0.2 PDF 253-254). Deleting the association removes them when unused, and an emptied `ioSpecification` |
| Pool boundary off / on          | the pool’s BPMNShape is removed and its content moved onto the diagram (process content of a shapeless participant, PDF 141-143); on again, a BPMNShape around that content                                                                                                                                                                                  |
| Event type                      | triggers allowed by the event's position (see spec-conformance.md); several make a Multiple event                                                                                                                                                                                                                                                            |
| Move / resize / auto layout     | BPMN DI bounds, waypoints and label bounds updated                                                                                                                                                                                                                                                                                                           |

## Shape library and “Change type”

The palette holds a searchable, collapsible BPMN 2.0.2 shape library
(`src/editor/library.ts`): start, intermediate (catch and throw), boundary
(interrupting and non-interrupting) and end events per trigger, tasks and their
markers, call activities, sub-process kinds, gateways, data, artifacts,
swimlanes, conversations and choreography activities. Every icon is drawn by the
canvas renderer (`renderPreview`). Click or drag an entry onto the canvas; from
the keyboard (Enter) the element is placed in the middle of the view (boundary
events on the selected activity, lanes in the selected pool). Drops are checked
by the modeling rules, e.g. error start events only go into an event
sub-process and a black-box pool cannot be the first pool of a process.

The context pad's “Change type” menu lists the variants of the same family the
element may become where it is (events in the flow across start / catch / throw /
end, boundary event triggers and interrupting mode, task types, sub-process
kinds including event sub-process, gateway kinds and the “X” marker, conversation
nodes, choreography task / sub-choreography). It runs
`element.replace`: type, triggers and flags in one undo step.

Modeling follows the BPMN 2.0.2 constraints listed in
[spec-conformance.md](spec-conformance.md) (sequence and message flow ends,
triggers per position, conditions and default flows, event sub-processes,
compensation, links, ad-hoc sub-processes). Files that already violate them stay
editable; the analyzer reports the violations.

Every edit is one undoable step, including compound ones (append, paste, auto layout).

Copy / paste / duplicate carry the semantics of flow nodes and the sequence flows
between them: event definitions (with their message, signal, ... references), loop
markers, conditions, default flows, documentation and attributes. Not carried: the
content of sub-processes, data associations, and boundary events (they are left
out of the copy). Cut deletes exactly what it copied.

Files with several diagrams (e.g. collapsed sub-processes drawn in their own
diagram, as Camunda Modeler 5 writes them) are editable: switch diagrams with the
selector in the header or “Open sub-process diagram” on a collapsed sub-process.
Deleting an element removes its DI from every diagram (and a sub-process's own
diagram); type changes re-point all of them. “Collapse” / “Expand” on the
context pad (or “Collapsed” in the properties) moves a sub-process's content
between the shape and its own diagram in one undo step.

All four BPMN diagram types (process, collaboration, conversation,
choreography) are editable. Opened read-only (shown as placeholders): the
remaining rarely used element kinds outside these tables, such as implicit throw
events.
